# 医疗小智

## 面向医院业务的多智能体医疗助手

**Spring Boot + LangChain4j + MongoDB + MySQL + Elasticsearch**

面试项目介绍

---

## 01 | 项目背景

传统医疗问答系统通常只能回答知识问题，无法可靠处理：

- 查询医生排班和剩余号源
- 预约、查询、取消挂号
- 医院科室知识问答
- 路线、天气等实时信息
- 医学报告文本提取、结构化和解释
- 多轮会话与用户隐私隔离

医疗小智将这些能力整合在一个可登录、多会话的 Web 应用中。

> 定位：医疗服务辅助系统，不替代医生诊断。

---

## 02 | 项目亮点

### 从“聊天机器人”升级为“可执行的业务系统”

- Leader + Worker 多智能体架构
- 确定性规则优先，LLM 作为兜底路由
- 医院业务工具与日期工具组合调用
- Elasticsearch 医学知识库混合检索
- Tavily 实时搜索
- 医学报告 OCR、文本提取、结构化与解释
- 用户账户、多会话、预约记录隔离
- Worker 失败、缺少信息和多任务场景统一交给 Leader 整合

---

## 03 | 总体架构

```text
浏览器前端
    |
+---v-------------------+
| Spring Boot API       |
| 认证 / 会话 / 文件 / SSE |
+---+-------------------+
    |
    v
MultiAgentOrchestrator
    |
    +--> 确定性路由规则
    |       |
    |       +--> Hospital Worker
    |       +--> RAG Worker
    |       +--> General Worker
    |
    +--> Leader Agent（复杂或不确定任务）
             |
             +--> Worker 执行结果
             +--> 多任务整合
             +--> 面向用户的最终答复
```

---

## 04 | 多智能体职责边界

| 组件 | 负责内容 | 主要能力 |
|---|---|---|
| Leader | 复杂任务分类、交接、结果整合 | 读取主会话，协调 Worker |
| Hospital Worker | 医院业务办理 | AppointmentTools、DateTools |
| RAG Worker | 院内知识和科室问答 | 关键词、向量、混合检索 |
| General Worker | 院外实时信息 | Tavily 搜索、路线、天气、新闻 |

每个 Worker 只访问自己的工具和私有记忆。工具调用轨迹、检索结果和内部状态不会进入用户可见的主会话。

---

## 05 | 路由与多任务处理

### 为什么不能只依赖 LLM 路由？

- “查号源”“取消预约”等关键词可以确定性识别
- 相对日期必须通过日期工具解析，避免模型凭空推断
- 一句话可能同时包含多个独立任务
- Worker 可能成功、失败或要求补充信息

### 处理流程

```text
当前用户消息
  -> 确定性规则
  -> 未命中时调用 Leader
  -> 拆分或交接子任务
  -> Worker 执行
  -> Leader 统一整合
  -> 只向前端输出一次答复
```

---

## 06 | 医院业务工具调用

### 典型预约链路

```text
用户表达预约意图
  -> 识别科室、医生、日期、时间段
  -> DateTools 解析“明天 / 未来三天”等相对日期
  -> 查询排班和剩余号源
  -> 收集姓名、身份证号、手机号
  -> 校验当前用户身份和预约冲突
  -> 写入 MySQL 预约记录
  -> 返回结构化预约结果
```

关键约束：

- 未收集完整个人信息时不能创建预约
- 不能使用模型猜测的个人信息
- 预约记录按登录用户隔离
- 数据库写入结果优先于模型自然语言描述

---

## 07 | 医学 RAG 与实时搜索

### 医学 RAG

- 知识源来自医院科室资料
- Elasticsearch 保存索引和向量
- 支持关键词、向量和混合检索
- 返回引用来源，降低无依据回答风险

### General Worker

- 处理路线、天气、新闻等时效性问题
- 通过 Tavily 查询外部信息
- 对实时数据设置超时和失败降级

医院内部知识和互联网实时信息分开处理，避免把过期或不相关内容混在一起。

---

## 08 | 医学报告多模态流程

支持：

- TXT
- 含文本层 PDF
- PNG
- JPG/JPEG

处理链路：

```text
上传文件
  -> 类型和大小校验
  -> 私有文件存储
  -> 本地文本提取或 OCR
  -> 结构化报告
  -> 指标解释和风险提示
```

安全边界：

- 文件不通过静态资源目录公开
- 结果不能替代医生诊断
- OCR 或模型失败时明确提示，不伪造识别结果

## 09 | 记忆、账户与数据隔离

| 数据 | 存储 | 隔离方式 |
|---|---|---|
| 用户和预约 | MySQL | `user_id` 归属当前账户 |
| 主会话 | MongoDB | 用户 ID + 会话 ID |
| Worker 私有记忆 | MongoDB | 独立 memory ID |
| 医学知识 | Elasticsearch | 独立索引 |
| 医学文件 | 私有文件目录 | 不暴露静态访问 |

主会话只追加用户和助手最终可见内容；工具参数、检索结果和内部轨迹保存在 Worker 私有记忆中。

## 10 | 主要难点与解决方案

### 难点一：路由错误会导致工具边界失效

**方案：** 确定性规则优先，Leader 只处理无法规则判断的复杂情况；给每个 Worker 明确工具清单和能力边界。

### 难点二：多轮对话中的上下文切换

**方案：** 主会话、Leader 交接信息和 Worker 私有记忆分层存储，避免把内部轨迹暴露给用户。

### 难点三：模型不能替代业务一致性校验

**方案：** 日期、号源、重复预约、用户身份和数据库写入由代码及工具完成，模型只负责理解和表达。

### 难点四：多命令请求不能被某个 Worker 提前结束

**方案：** Worker 统一返回结构化执行结果，由 Leader 整合后再输出最终答复。

## 11 | 工程化与测试

- 统一 REST API 和 SSE 流式响应
- 认证、退出、注销和多会话管理
- 文件类型、大小、路径和日志脱敏控制
- 外部模型、OCR、搜索和 Elasticsearch 可配置
- readiness 配置检查接口
- 多模块单元测试和集成测试
- 200 条多样化路由测试用例，覆盖医院、RAG、实时搜索、混合意图和兜底场景

面试时重点展示：一个多命令请求如何被拆分、执行、失败处理并最终整合。

## 12 | 演示脚本

### 场景 A：医院业务

```text
帮我查一下未来三天神经内科的号源，并预约明天上午刘文华医生
```

展示：日期解析、号源查询、个人信息收集、预约写入和结果确认。

### 场景 B：知识问答

```text
介绍一下你们医院的神经内科
```

展示：RAG 检索、引用来源和与医院业务工具的边界。

### 场景 C：混合任务

```text
查一下神经内科近期排班，再告诉我从北京大学怎么去医院
```

展示：Hospital 与 General 两个 Worker 的串联、Leader 交接和统一答复。

---

## 13 | 项目价值

医疗小智体现的不是“调用一次大模型 API”，而是：

- 如何把 LLM 接入真实业务流程
- 如何限制模型能力边界
- 如何处理工具调用、状态、权限和失败
- 如何把知识库、实时搜索和多模态能力组合起来
- 如何保证多用户环境下的数据隔离

**核心关键词：Agent Orchestration、Tool Calling、RAG、Memory、Multimodal、Security、Evaluation**
